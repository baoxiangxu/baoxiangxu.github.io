## Folder layout

```
│   ├── components/

│   │   ├── content/      hero text, academic column, paper dialog
│   │   ├── controls/     theme toggle + backdrop-visibility slider
│   │   ├── gallery/      photo grid and lightbox
│   │   ├── logo/  footer/  speedDial/  theme/
│   │   ├── hooks/        reduced-motion, in-viewport
│   │   └── utils/        name, styles, three.js helpers
│   └── content/          ← ALL EDITABLE CONTENT LIVES HERE (see its README)
├── public/               static assets copied verbatim into the build
│   ├── files/            CV and downloadable archives
│   └── images/           GENERATED by `npm run images` — never edit by hand

├── .github/workflows/    CI: builds and publishes to GitHub Pages on push
└── build/                production build output (git-ignored, never committed)
```

## Where to change things

| What | File |
| --- | --- |
| Name, hero line, About paragraphs, contact links | `src/content/profile.json` |
| Education timeline | `src/content/education.json` |
| Publications (title, authors, journal, abstract, figure, tags) | `src/content/publications.json` |
| Projects | `src/content/projects.json` |
| Gallery headings, blurbs and photo lists | `src/content/galleries.json` |
| Brand colours | `src/content/theme.json` |
| Page title, description, structured data | `public/index.html` |
| CV PDF | `public/files/resume.pdf` |

Nothing in `src/components/` needs editing to change what the site says.

## Development

```bash
npm install     # install dependencies
npm start       # dev server at http://localhost:3000
npm run build   # production build into build/
npm run preview # serve build/ locally, prints a LAN address for phone testing
npm run images  # regenerate every web-sized image from originals/
```

After `npm run build`, double-click **`本地预览.command`** (macOS) or
**`本地预览.bat`** (Windows). Both just run `scripts/preview.js`, so all three
platforms execute identical code.

Everything here runs on Windows, macOS and Linux:

- preview and build need only **Node.js**
- `npm run images` needs **Python with Pillow**, and locates whichever Python
  the machine has (`py`, `python` or `python3`)
- the icon and social-card generators resolve fonts per platform rather than by
  absolute path

## Images

`originals/` is the only place source images go; everything under
`public/images/` is generated by `npm run images` and should never be edited.

| Source | Generated |
| --- | --- |
| `originals/avatar.jpg` | `avatar-360.webp` |
| `originals/photos/<gallery>/*.jpg` | `<gallery>/thumbs/*.webp` (640 px short side, the grid) and `<gallery>/large/*.webp` (2000 px long side, opened on click) |
| `originals/figures/*` | `cards/*.webp` (520 px card thumbnail) and `figures/*.webp` (1400 px, shown in the paper dialog) |

Visitors never download the camera originals — 115 MB that would otherwise be
copied into every build. WebP only: a JPEG twin for pre-2020 browsers cost 29 MB
and doubled the file count for under 3% of visitors. Flip `JPEG_FALLBACK` in the
script to restore it.

Adding photos: drop them in `originals/photos/food` or `originals/photos/travel`,
add the filenames to `src/content/galleries.json`, then run `npm run images`.
Requires Python with Pillow (`pip install pillow`).

Other generators:

```bash
python3 scripts/make_social_image.py public/social-image.png   # link-preview card
python3 scripts/make_icons.py public                            # favicons / app icons
```

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which installs,
builds and publishes to GitHub Pages. No build output is ever committed.

One-time repository setting: **Settings → Pages → Source → GitHub Actions**.

`200.html` is a copy of `index.html` so deep links resolve in this single-page app.
